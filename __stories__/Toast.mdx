        <h2>When to use</h2>

        <ul>
          <li><strong>Confirmations</strong> — a save completed, a member was invited, a backup was triggered.</li>
          <li><strong>Background status</strong> — a long-running job finished while the user was elsewhere.</li>
          <li><strong>Non-critical errors</strong> — a request failed but the user can retry without losing context.</li>
          <li><strong>Transient system state</strong> — the service went offline and came back.</li>

        <h2>When not to use</h2>

        <ul>
          <li>For decisions that require a response → use a <code>Modal</code>.</li>
          <li>For errors that block the current task → use an inline <code>Alert</code>.</li>
          <li>For marketing messages or onboarding tips → use a banner or coach mark.</li>
        </ul>

        <h2>Writing</h2>

        <ul>
          <li>Lead with the outcome — <em>Cluster created</em>, not <em>POST /clusters returned 201</em>.</li>
          <li>Keep messages under 120 characters — two short sentences at most.</li>
          <li>For errors, say what went wrong and what to do next.</li>
        </ul>

        <h2>Duration</h2>

        <ul>
          <li>Success and info: <strong>5 000 ms</strong> (default).</li>
          <li>Warnings: consider <strong>10 000 ms</strong> when the message is actionable.</li>
          <li>Errors that must be acknowledged: <code>Infinity</code>.</li>
        </ul>

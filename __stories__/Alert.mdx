Alert is an inline, in-page message that draws attention to the state of a task or region. Unlike a Toast, it stays put — use it to surface validation results, blocking errors, or contextual guidance right where the user is working.

        <h2>When to use</h2>

        <ul>
          <li><strong>Validation results</strong> — summarise what went wrong after a form submission.</li>
          <li><strong>Contextual status</strong> — communicate that a region is read-only, degraded, or in maintenance.</li>
          <li><strong>Blocking errors</strong> — an action failed and the user must react before continuing.</li>
        </ul>

        <h2>When not to use</h2>

        <ul>
          <li>For transient confirmations that can auto-dismiss → use a <code>Toast</code>.</li>
          <li>For decisions that require a response → use a <code>Modal</code>.</li>
          <li>For a compact one-line status with an optional link → use a <code>Notification</code>.</li>
        </ul>

        <h2>Intent</h2>

        <ul>
          <li><strong>success</strong> — an operation completed as expected.</li>
          <li><strong>info</strong> — neutral, non-urgent context.</li>
          <li><strong>warning</strong> — the user should review something before proceeding.</li>
          <li><strong>critical</strong> — an error that blocks the current task.</li>
        </ul>

        <h2>Writing</h2>

        <ul>
          <li>Lead with the outcome in the <strong>title</strong>; keep the <strong>content</strong> to one or two short sentences.</li>
          <li>For errors, say what went wrong and what to do next.</li>
          <li>Keep actions to one primary path — a button and, at most, one supporting link.</li>
        </ul>
      </>
